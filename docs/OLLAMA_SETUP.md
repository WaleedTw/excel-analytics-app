# تشغيل النموذج المجاني محليًا

## لماذا Ollama؟

يعمل `llama3.2` على جهاز المستخدم ويقدم API محليًا على `http://127.0.0.1:11434`. لا يحتاج مفتاح OpenAI أو رصيد API، ولا تُرسل بيانات المصنف إلى خدمة سحابية.

## خطوات Windows

1. ثبّت [Ollama for Windows](https://docs.ollama.com/windows) وافتح التطبيق.
2. من PowerShell داخل جذر المشروع شغّل:

```powershell
.\scripts\setup-ollama.ps1
```

3. شغّل backend:

```powershell
.\scripts\run-backend.ps1
```

4. افتح `http://127.0.0.1:8001/api/v1/health`. الحالة الصحيحة للعرض:

```json
{
  "status": "ok",
  "mode": "ollama",
  "model": "llama3.2",
  "llm_ready": true
}
```

## الإعدادات

| المتغير | الافتراضي | الغرض |
|---|---|---|
| `LLM_PROVIDER` | `ollama` | `ollama` للتشغيل الحقيقي أو `mock` للاختبارات |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | عنوان Ollama المحلي |
| `OLLAMA_MODEL` | `llama3.2` | اسم النموذج المحلي |
| `OLLAMA_TIMEOUT_SECONDS` | `120` | مهلة توليد خطة التحليل |

يمكن نسخ `.env.example` إلى `.env` لتعديل القيم. يقرأ backend الملف تلقائيًا.

## معالجة الأخطاء

- `Ollama غير متاح`: افتح تطبيق Ollama، ثم أعد تحميل الواجهة.
- `النموذج غير محمّل`: نفّذ `ollama pull llama3.2`.
- إذا أعاد النموذج JSON غير مطابق أو أسماء أعمدة مختلقة، يرفض LangGraph الخطة ويتوقف بأمان قبل الحسابات.
- لا يوجد fallback صامت إلى Mock في التشغيل الحقيقي؛ هذا يمنع تقديم العرض على أنه AI حقيقي بينما يعمل بردود مبرمجة.

## حدود البيانات المرسلة للنموذج

يرسل `agent.py` أسماء الأعمدة والأنواع والأدوار الدلالية وعدد القيم المفقودة/الفريدة وملخص الجودة. يحذف `sample_values` ولا يرسل صفوف Excel. كل الحسابات الرقمية تنفذ لاحقًا في Python وDuckDB.
